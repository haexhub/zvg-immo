- Keep each change self-contained and easy to review, grouping production code, relevant tests, documentation, and configuration that describe the same behavior, and splitting independent refactors and unrelated cleanups into separate changes. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Keep each task isolated in its own worktree and topic branch so that changes can be reviewed, tested, committed, and removed independently. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Keep related tests close to the behavior they verify according to the language and repository convention, and move tests, documentation, fixtures, and call sites together with a module split. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Keep side effects at visible boundaries so that pure calculations and decisions are easy to test without a database, network, filesystem, clock, or global mutable state. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Name code after its domain meaning and behavior instead of relying on a comment to explain an otherwise opaque `data`, `helper`, or `process` function. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Organize code around cohesive domain or feature boundaries where the codebase supports it. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Prefer a change that clearly improves maintainability and correctness over theoretical perfection, and when a design is uncertain make the smallest reversible change that provides evidence about the next decision. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Prefer early returns or named helpers when they make the main path easier to follow, reducing nesting. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Refactor repeated behavior when the shared rule is real and the abstraction makes both callers clearer, keeping the abstraction close to the domain that owns it rather than in a generic utility module that becomes a dumping ground. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Separate broad formatting or mechanical refactors from behavior changes when possible, because mixed diffs make review, debugging, rollback, and blame less reliable. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Treat a change of about 100 net lines as a useful review-size warning and a change approaching 1000 lines as a strong prompt to split the work or to agree on the larger change in advance, identifying generated code, mechanical renames, and required migrations as legitimate exceptions. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Use the smaller soft thresholds as prompts for review rather than automatic failures: a function beyond roughly 40–60 lines, or nesting deeper than roughly three levels, deserves a deliberate look at whether it is still one coherent unit or hides distinct responsibilities. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Before a raw `grep`/`rg` search or broad file reads, build a bounded, task-specific context map for any question about the codebase — what something does, where it lives, how pieces relate, which existing artifact might already satisfy a request, or how to trace a symptom back to its source, including exploratory lookups incidental to a larger task: state the concrete intent as a question, choose a small token budget starting around 800–1500 tokens and raise it only when the returned relationships are insufficient, run `graphify query "<intent>" --budget <N>` (with `--dfs` for a narrow dependency path, or `graphify path` and `graphify explain` when one specific relationship or symbol is needed), then treat the result as a navigation aid, extract the cited source locations, symbols, and relationships, and read only the smallest source slices needed; the only exemption is a local one-file edit at a symbol whose location is already known from earlier in the same task, and authoring a new named artifact still requires the graph consultation even where a context map would be unnecessary. _[from `com.github.haexmas.atoms.graphify-first-authoring/graphify-context-map`]_
- Preserve in the resulting context map, when available, the task intent and token budget, the selected files and symbols, the relevant edge or call relationship, source locations for every claim, and an explicit truncation or failed-consultation note. _[from `com.github.haexmas.atoms.graphify-first-authoring/graphify-context-map`]_
- Read the graph's output against rough thresholds that operator judgment overrides: six or more identical lines with the same logic across candidates call for extraction and a refactor proposal, fewer than five purely structural lines (setup, error-wrapping, adapter boilerplate) are often fine left alone, and hits inside test files are usually left alone unless they are helper functions. _[from `com.github.haexmas.atoms.graphify-first-authoring/graphify-first-authoring`]_
- Favor the shortest working diff once the problem is understood, deletion over addition, boring over clever, and the fewest files possible. _[from `com.github.haexmas.atoms.ponytail/ponytail`]_
- Question complex requests by asking whether X is actually needed or whether Y already covers it. _[from `com.github.haexmas.atoms.ponytail/ponytail`]_

## SHOULD_NOT

- Apply a blanket `ast-grep` rewrite merely because the pattern matches. _[from `com.github.haexmas.atoms.ast-grep/ast-grep-structural-search`]_
- Install a package automatically to obtain `ast-grep`, or treat the absence of this optional tool as a failure to adopt the capability. _[from `com.github.haexmas.atoms.ast-grep/ast-grep-structural-search`]_
- Assume that a platform-specific global or API exists everywhere, because browser, Node.js, and serverless environments have different APIs and failure modes. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Catch an error merely to log and rethrow it unchanged, which usually duplicates logs and loses ownership of the failure decision. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Introduce a barrel export or a new abstraction only to shorten an import path. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Leave promises unhandled. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Replace repository tooling with a personal global installation. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Use `||` where a valid value such as `0`, `false`, or `""` must be preserved, or hide a required value behind optional chaining without deciding how absence is handled. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Use mutation or shared mutable module state as an accidental communication channel. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Create circular imports or dependencies between modules. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`, `com.github.haexmas.atoms.general-coding/general-coding`]_
- Assume that a test file is discovered unless the runner configuration confirms it. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript-testing`]_
- Leave floating promises in a test, or let a test pass before the asynchronous work it is meant to verify has completed. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript-testing`]_
- Mock the unit's own logic so thoroughly that the test only verifies the mock wiring. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript-testing`]_
- Rely on real network calls, shared mutable state, random values without a controlled seed, or arbitrary timer sleeps in tests. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript-testing`]_
- Turn every test into a slow end-to-end test. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript-testing`]_
- Abstract two things merely because they look similar, before establishing that they share behavior, ownership, change reason, and invariants; a small amount of local duplication is preferable to a premature generic abstraction that couples unrelated callers. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Create folders only for superficial symmetry, such as putting every small class, interface, or helper in its own folder. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Enforce a universal maximum for functions, files, or pull requests, because domain complexity, cohesion, control flow, and the number of reasons to change are more meaningful than a line count. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Rely on hidden global state, re-export everything, add pass-through modules that create no boundary, or let a domain layer know about infrastructure details. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Scatter one simple operation across many microscopic functions. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Split a file solely to make it shorter. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- Use comments to narrate code that could be made clear through structure and naming. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_

## MAY

- Opt out of individual TypeScript strict checks during a migration in an existing project, provided that choice is made explicit. _[from `com.github.haexmas.atoms.coding-guideline-javascript-typescript/javascript-typescript`]_
- Exceed the 500 LoC boundary in generated files, vendored code, snapshots, and other files not normally edited by hand, which should be excluded from that assessment. _[from `com.github.haexmas.atoms.general-coding/general-coding`]_
- The operator may suspend the graph-consultation rule for the current session with any natural-language request to that effect — honor the intent rather than a specific phrase — where the suspension applies only to the current session, must be re-issued in a new session to apply again, and does not exempt the response from noting which artifacts would have been flagged had the rule been active. _[from `com.github.haexmas.atoms.graphify-first-authoring/graphify-first-authoring`]_
